# Migrating to `studion/core` v5

## Breaking changes

### Node.js 22 or newer

The following Node-oriented APIs require Node.js 22 or newer:

- `core/ensure_pkg_manager`
- `core/install_dependencies`
- `core/run_script`
- `core/install_and_run`

Before upgrading, update older `core/node` and `core/node_secrets` tags, `install_and_run.node_tag` values, custom Docker images, and machine executors. A floating `lts` tag requires no change when it already resolves to Node.js 22 or newer. An affected command running on an older version fails with:

```text
At least Node.js v22 is required!
```

### Package-manager versions

Direct prerelease and build-version package-manager specifiers are unsupported. Registry dist-tags are accepted only when they resolve to a stable `X.Y.Z` version. Before upgrading, replace a tag such as `next`, `beta`, or `rc` when it currently resolves to a prerelease; use a stable exact version, numeric partial version, or stable-resolving tag instead.

### Dependency caching

`core/install_dependencies` and `core/install_and_run` now restore and save the exact `cache_path` and configure npm or pnpm to use it during dependency installation. For npm, this is the cache directory. For pnpm, it is the configured `store-dir` root, not the versioned directory reported by `pnpm store path`.

No cache configuration change is required when a job uses one package manager and the default path. Set `cache_path` when retaining a custom cache location. If the same job invokes `install_dependencies` for both npm and pnpm, give the two invocations separate paths.

A custom path must be absolute or begin with `~/`, be creatable and writable, and not resolve to `/` or the current user's home directory.

`core/ensure_pkg_manager` ensures that pnpm is available, but it does not persist the v5 store setting for later custom steps. If a custom step runs `pnpm install`, configure `store-dir` explicitly or move that installation to `core/install_dependencies`; `core/install_and_run` already uses the orb-managed path.

The first v5 run may use a cold cache because the cache identity and layout changed. No manual cache clearing or `cache_version` change is required solely for the upgrade.

## Upgrade

1. Upgrade affected execution environments to Node.js 22 or newer while still using `studion/core` v4. Run `node --version` in each affected job and confirm that its major version is 22 or newer.
2. Review whether the cache cases above require an explicit `cache_path`.
3. Update the orb reference to `studion/core@5.0.0`, adding any required `cache_path` in the same change.
4. Run the v5 pipeline. A cold cache on this run is expected; rerun it without changing the lockfile to verify that the new cache restores successfully.

```yaml
orbs:
  core: studion/core@5.0.0

workflows:
  test:
    jobs:
      - core/install_and_run:
          node_tag: "22"
          pkg_manager: pnpm
          cache_path: ~/.cache/pipeline-core-orb/pnpm # Optional custom store root
          script: test
```

The explicit `node_tag` pin is only needed when the existing executor tag provides Node.js below 22.
